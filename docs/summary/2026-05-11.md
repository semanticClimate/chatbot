Brief Q&A about the in-app message: *“You've hit a temporary usage limit. Wait a minute and try again.”*

## Is it Cloudflare?

**No.** That exact user-facing text is produced by application code in `climate_streamlit/llm/ask.py`: in the outer `except` block, when the exception string contains `rate_limit` (case-insensitive), the handler returns that message in the answer `blocks`.

## Is it the Mac serving FastAPI?

**The response is assembled on your backend** — if that is FastAPI on your Mac, the HTTP response originates there. **The limiting party is not “the Mac” in general:** the usual trigger is an upstream API error that includes `rate_limit` in its message (after your server calls out to that API). FastAPI is where the exception is caught and mapped to friendly copy.

Integration path referenced in this repo: `climate_streamlit/api_server.py` → `chat_service.run_ask` → `ask_groq` (`climate_streamlit/services/chat_service.py`).

## Is it Groq?

**Almost certainly yes** for normal chat completions. `ask_groq` calls `groq_client.chat.completions.create(...)` inside the same `try` that feeds the `rate_limit` branch; parsing/normalization failures are unlikely to mention `rate_limit`. So in practice this points to **Groq rate limits** (tier / TPM / RPM) for your API key unless some other layer injects `rate_limit` into the exception text.

## Debugging tip

Inspect **`operator_detail`** (and logs) on affected responses — it records `exception_type` and `exception_message`, which confirms the upstream error string.
