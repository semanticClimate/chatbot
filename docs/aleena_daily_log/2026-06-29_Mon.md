
# IPCC AR6 Climate Chatbot - Progress Brief (Second Attempt)
> As of 29<sup>th</sup> June 2026

## Background
On 26 June 2026, development began on a chatbot designed to answer questions grounded in the IPCC AR6 Synthesis Report ,returning cited, science-based answers drawn directly from the document rather than from a general-purpose language model.
The first attempt was discarded. This brief documents what was built, why it was abandoned, and what replaced it.

## I. Current Build
The rewrite began on 28 June 2026 with a deliberate constraint: one terminal starts the whole backend.

The new stack is Flask, ChromaDB, and Ollama, nothing else. Celery and Redis were removed entirely; the RAG pipeline runs synchronously in the request cycle. The frontend is plain HTML, CSS, and JavaScript with no build tools. Ingestion is a single script run once. The entire backend is five files.

The same core capability is preserved: the IPCC report is chunked, embedded, and stored in ChromaDB; questions retrieve the most relevant passages; Llama 3.2 generates a grounded, cited answer. What changed is everything around it.

As of 29 June, the chatbot is running end-to-end. Questions return accurate, cited answers. A Cloudflare tunnel script allows the backend to be shared publicly without port forwarding. A guided onboarding tour, conversation history, downloadable transcripts, and a version number pulled from config.toml have been added. The frontend is a three-panel layout ,sidebar, chat, and an embedded source panel showing the AR6 report.

## II. Testing ,  cabot-semanticclimate.org

The live Climate Academy chatbot at cabot-semanticclimate.org was tested across both desktop and mobile to evaluate behaviour, answer quality, and UI consistency.

### Mobile UI
Three issues were observed on mobile. First, the sidebar fails to render correctly, making New Chat and other sidebar features inaccessible. Second, the initial chat screen before any question is asked appears clean and well-designed with no visible issues. Third, after the chatbot returns its first response, the layout breaks ,  elements become misaligned and the interface no longer matches its pre-conversation state. This suggests a re-render issue triggered specifically by the first response arriving.

### Answering
A broad range of questions was asked across multiple sessions. Several patterns emerged.
#### Suggested questions that don't work
One of the pre-loaded suggested prompts reads "What is Climate Academy?" but the chatbot responds with "I could not find that in the Climate Academy materials." 

#### Multiple questions in one message 
The chatbot accepts multi-question inputs but handles them inconsistently. When eleven questions were sent together, only four were answered fully; the rest returned "there is no mention of X in the provided passages." The same questions asked individually returned correct answers. This suggests the retrieval step is fetching a fixed number of chunks that can only cover a limited number of topics at once, meaning questions later in a batch often miss relevant context.
Single questions asked individually ,  performance was generally good. The chatbot correctly defined greenhouse gases, the Keeling Curve, the Milankovitch cycles, social tipping points, the Warming Stripes visualisation, the Montreal Protocol, the biosphere, and the Sixth Mass Extinction, among others. Citations were grounded and responses were coherent.

#### Knowledge gaps 
Several questions that should be answerable returned nothing: "What is climate anxiety?" initially failed before returning a correct answer in a later session, "What is systems thinking?" failed in a batch but succeeded alone, and "What is the Great Oxidation Event?" was incorrectly described as the same event as the Great Dying in one response.

#### Summary
The chatbot performs reliably for single, well-scoped questions drawn from the book's core content. It struggles with multi-question inputs, a handful of suggested prompts that fall outside what the retrieval layer can find, and a mobile layout that breaks after the first response. These observations directly informed design decisions in the IPCC AR6 chatbot ,  particularly the choice to improve prompt phrasing, handle casual inputs separately, and design the frontend to be layout-stable across all interaction states.

## III. semanticClimate Blog
Alongside the chatbot development, a blog post was written for the semanticClimate website documenting a related project: the Climate Academy chatbot, a collaborative effort between Climate Academy, semanticClimate, and the Open Knowledge Foundation as part of OKFN's AI Learning Labs initiative.

The blog covers the rationale for building a responsible climate chatbot ,one grounded in a trusted source, Climate Academy: The Student Guide by Matthew Pye, written for high school students. It outlines the chatbot's workflow and makes the case for what responsible AI in the climate space actually means in practice: reliable knowledge drawn from credible sources, transparency through visible citations, fairness in representing how climate change affects different communities, and accessibility through plain language.

The piece serves as both documentation of the Climate Academy chatbot and a broader argument for why the design principles behind it ,source-grounded answers, citation transparency, and accessible language ,matter when the subject is something as consequential as climate change. These same principles directly inform the design decisions made in the IPCC AR6 chatbot being built in parallel.

### What Comes Next
Planned additions include a resizable source panel, Wikipedia as a fallback knowledge source when the IPCC report does not cover a question, persistent multi-session conversation history with rename support, and a CSS/JavaScript refactor to move from a single monolithic file to a modular file structure. A migration to React is under consideration for a later phase.
