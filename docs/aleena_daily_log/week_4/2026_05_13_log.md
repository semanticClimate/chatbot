### What I Learned About the Project Architecture

The `docs/architecture` folder helped clarify the real structure of the project.

The chatbot is not just one simple app — it is a modular three-part system:

- **web_client/** → Static frontend (HTML/CSS/JS)
- **fastapi_app/** → Main backend handling RAG, Groq, and book serving
- **climate_streamlit/** → Streamlit version mainly used for testing and rapid development

---

### Key Understandings

- The frontend and backend are separate systems and can run on different URLs
- The browser cannot directly read local book files, so FastAPI serves the book securely
- Cloudflare tunnels allow both frontend and backend to be accessed remotely
- Citation jumps work using iframe communication (`postMessage`)
- ChromaDB indexing is done once, so the app does not process the full book every time
- Professional UI was achieved using Vanilla JavaScript without needing React or Vue

---

### Main Takeaway

The project is far more scalable and flexible than initially assumed because:

- Frontend can be hosted anywhere
- Backend can be swapped or updated independently
- Modular architecture improves debugging, maintenance, and future upgrades

> Note to self: Understanding architecture early prevents major confusion later when debugging deployment, frontend-backend communication, or feature expansion.
